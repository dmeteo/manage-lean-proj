# Журнал использования ИИ

## Назначение и фактический вклад

Запись от 26.11.2026. Использован Codex в настольном приложении, с подключённым GitHub и инструментами чтения чатов/файлов. Точное обозначение модели и время работы не измерялись. Цель — сопоставить расшифровку, рабочее ТЗ и критерии, подготовить единый проект документации для независимого ревью разработчиков и сократить ручную подготовку повторяющихся разделов.

ИИ создал тексты шести Markdown-документов: README, BACKEND_SPEC, API_CONTRACT, CONTRIBUTING, ROADMAP, AI_USAGE; также правила .gitignore и пустые .gitkeep. **Код приложения, MSW, OpenAPI, миграции и тесты приложения не генерировались.** Объём фиксируется перечнем этих шести документов; доля ИИ в будущем коде, часы экономии и количество токенов не измерялись.

## Выполненные действия

| Действие | Инструмент | Проверенный факт |
|---|---|---|
| Восстановление задания и рабочего контекста | чтение связанных чатов | прочитаны требования публикации и организация команды |
| Чтение исходников | локальное чтение TXT, извлечение PDF и DOCX | изучены расшифровка, 7 страниц рабочего ТЗ и текст критериев |
| Проверка репозитория | подключённый GitHub | на исходной проверке репозиторий публичный, пустой, веток нет, права push подтверждены |
| Подготовка документов | Codex | требования рабочего ТЗ отделены от подтверждений заказчика и предложений |
| Самопроверка | Codex | сопоставлены роли, статусы, DTO, ограничения, сроки и сценарии; независимая экспертиза не проведена |
| Локальная проверка комплекта | проверка файлов и разбор JSON | ровно 6 Markdown и 9 файлов всего, 8 относительных ссылок существуют, 9 JSON-примеров корректны, блоки кода закрыты; кода приложения нет |

Первоначальная попытка создания .gitignore через GitHub-плагин завершилась 403 Resource not accessible by integration, несмотря на push:true в метаданных. Плагин не внёс изменений. После этого пользователь выбрал публикацию через обычный Git и GitHub CLI от своего аккаунта; вход подтверждён. Для пустого репозитория подготовлен базовый коммит только с .gitignore и отдельная ветка docs/backend-contract-v01 с документацией. Итоговые SHA и результат публикации следует проверять в истории Git и PR; бизнес-решения и API этим не утверждаются.

## Ошибки и ограничения

При подготовке выявлены противоречия самого рабочего ТЗ: проект создаёт координатор в разделе ролей, но РП в приёмке; похожее расхождение у ручной федеральной отчётности. Одного «На проверке» недостаточно для двух ступеней внутреннего контроля. Условие завершения по внутренней приёмке расходится с описанием финального внешнего контроля во встрече. Все эти вопросы вынесены в решения D2–D4, предложенные ответы не считаются согласованными.

В процессе чтения документов отсутствовал модуль pymupdf; PDF успешно извлечён через pypdf. Первый вывод столкнулся с кодировкой терминала, повторное чтение в UTF-8 прошло успешно. Один запрос контекста превысил разрешённую длину параметра; исправлен и повторён. Эти ошибки инструментов не являются дефектами приложения.

Не получены методические указания РЦК, утверждённые формы/формулы, API внешних систем. Текстовое извлечение PDF не является проверкой визуального оформления оригинала. Предложения ИИ о cookie, моделях, статусах, CSV и сроках требуют ревью. Результаты приложения и достигнутые ≥60% не заявляются.

## Человеческие доработки и независимая проверка

На момент подготовки человеческое редактирование этих документов, одобрение архитектуры и запуск приложения не подтверждены. Самопроверка ИИ не заменяет backend-ревью, согласование frontend и приёмку тимлида/заказчика.

Будущая запись участника:
- дата, автор и версия/SHA;
- задача и инструмент/модель, если известна;
- какие фрагменты предложены ИИ и их измеримый объём;
- что человек изменил и по какой причине;
- фактически выполненная проверка и результат;
- найденные ошибки, ограничения и решения;
- источник заимствований и условия лицензии.

## Лицензии и конфиденциальность

Тексты прямо обозначены как подготовленные с помощью ИИ. В репозиторий включается обезличенное изложение требований; оригиналы внутренних документов, транскрипт, реальные имена/контакты, секреты и файлы заказчика не публикуются. Чужой исходный код и медиа в этой поставке не используются, зависимости приложения не добавлены.

Разрешение на публичную публикацию оригиналов заказчика не предполагается. Общая лицензия проекта пока владельцем не выбрана; публичность GitHub сама по себе не даёт неограниченную лицензию на повторное использование. Команде перед включением стороннего кода/медиа/пакетов проверить их конкретные лицензии и применимые условия ИИ-сервиса; юридическая экспертиза не проводилась. Не выдавать сгенерированное за полностью самостоятельное творчество участника.
